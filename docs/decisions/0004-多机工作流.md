# 0004 三台电脑的工作流；GitHub 只同步；实机测试的安全规则
日期：2026-11-23　状态：有效（实机测试部分尚未实施）

## 决定
**GitHub 只用来同步代码**，不跑自动化测试（2026-11-23 否决了"GitHub 自托管运行器"）。三台电脑都装 Claude Code，各自在本地跑测试。

| 电脑 | 做什么 | 能不能改代码 |
|---|---|---|
| 开发机（插 USB 设备） | 主要开发；软件测试；USB 设备的实机测试 | 能，`main` 只在这里合并 |
| 工控机1（4 块板卡） | 实机测试；现场排查 | 只改本机台架清单；修 bug 开 `fix/ipc1-…` 分支推上去 |
| 工控机2（≥8 块板卡） | 同上 | 同上（`fix/ipc2-…`） |

分支：`main` 始终可运行，合并前 `.\scripts\verify.ps1` 全过；`feat/…`、`fix/…` 短分支，合并后删除。工控机上只 `git pull --ff-only`，从不在 `main` 上提交。

实机测试（计划，`lab/` 目录尚未建立）：
1. **台架清单** `lab/benches/<电脑名>.yaml`：这台机器装了哪些板卡（型号、板卡号或槽位、COM 口、驱动版本），**每个输出通道接了什么、允许的范围**，自检接线（哪个输出接到哪个输入）。测试代码不写死任何硬件信息，按电脑名读清单。
2. **测试标记"需要哪块硬件"**：每台机器执行同一个命令，有这块板卡就跑，没有就跳过；报告列出"因缺硬件跳过"的测试，避免误以为测过了。
3. **三级测试**：只读识别 → 回环自检 → 带负载输出。后两级必须人工确认开关；每台工控机**第一次**跑实机测试时人必须在场。
4. 安全状态放在 `finally` 里；测试"进程被杀"时设备是否回到安全状态（SDK 子进程在 stdin 关闭时回安全态，要实测）。
5. 同一台机器同一时间只允许一次实机测试；SAGE 程序开着占用板卡时拒绝启动。
6. 结果：完整日志留在本机；摘要推到**这台机器自己的分支** `lab/<电脑名>`，永远不推 `main`，避免三台机器抢着推。
7. 每个插件 README 记录"实机验证状态"：在哪台机器、哪个提交上验证过，或"未验证"。
8. 除了在开发环境跑插件测试，还要用**正式安装包 + `.sagedev`** 走一遍安装路径，那才是客户实际用的方式。

## 原因
- 用户希望 GitHub 只做同步；三台电脑各有 Claude Code，可以就地运行和排查。
- 这些插件还没上过实机，第一次就可能拉继电器、输出电压，必须先有安全规则。
- 早先方案"工控机只 pull，但又把结果提交到 main"自相矛盾（审核指出），改为每台机器推自己的 `lab/<电脑名>` 分支。

## 怎么执行
- 硬件准备不足，实机测试**以后再做**（2026-11-23）。到时先在开发机用 USB 转串口、TX 和 RX 短接做试点，再上工控机。
- 厂商 DLL 在其中一台工控机上，存放办法（共享盘加哈希清单，或私有仓库 LFS）到时一起定。
- 工控机环境安装要准备 `scripts/setup.ps1`；Electron 下载可能被网络拦，需要镜像或离线包（见 `docs/status.md`）。
