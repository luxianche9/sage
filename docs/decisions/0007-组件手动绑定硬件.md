# 0007 上位机组件靠手动绑定关联硬件；插件不声明数据流和工具的关系
日期：2026-11-25　状态：有效

## 决定
- 画布上的组件和硬件的关联**由用户在组件属性里手动绑定**。每个组件存一份绑定，分两半：
  - **读**：设备 + 数据流（开关量再加"第几位"）——它显示什么。
  - **写**：设备 + 工具 + 固定参数 + "操作员的值填进哪个参数"（开关再加两个状态各发什么值）——它调用什么。
- **插件不声明"这条流由哪个工具控制"**（用户 2026-11-25 否决）。`plugin/tools/skill/device-plugin/references/streams.md` 里的"声明而不关联"保持不变：流和工具在程序里互不引用。
- **不恢复按参数名猜绑定的做法**（旧前端 `control-bindings.ts` 用正则猜 `channel`、`relay` 这类参数名，在标签 `archive/teststand-hmi` 里）。
- AI 仍可用 `update_monitor` 写同样的绑定，操作员确认后生效；它写的和手动选的是同一种数据。

## 原因
- 用户选择只做手动绑定：SDK 和 13 个插件都不用改，插件作者不多一项要维护的声明。
- 手动绑定是任何方案都要有的兜底（插件没声明、非常规组合），只做它，一条路走通。
- 猜出来的绑定错了不容易发现：点了没反应，或者动了别的通道。

## 怎么执行
- 把数据流拖到画布上只生成**显示类**组件（数值、指示灯、波形、终端、报文表）。要能操作，拖一个开关 / 滑块 / 按钮，在属性里依次选：设备 → 动作 → 固定参数 → 值填进哪个参数 → 读回看哪条流（哪一位）。
- 属性里的动作列表只列会改变输出的工具（`actuate`、`configure`；按钮还可选 `safe`），参数按工具自己的参数定义列出；滑块的量程默认取该参数声明的最小最大值。
- 为了少重复劳动：绑好一个组件后可以"复制并递增"（通道号和位号各加一），一排 16 路继电器绑一次、复制 15 次。
- 加载时拿绑定对照设备的工具清单，工具或参数对不上就在组件上标"绑定失效"，不能点了没反应。
- 组件显示读回来的状态，不显示刚才点的状态；没有读回流的写"设定值"。测试占用设备、记录页回放、设备离线时置灰并写明原因。
- 项目文件里已有的 `panel.sources`（读）和 `MonitorControl`（写）是这两半的雏形，要补"第几位"和开关两个状态的值。
