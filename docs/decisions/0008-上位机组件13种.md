# 0008 上位机画布的组件定为 13 种
日期：2026-11-25　状态：有效

## 决定
画布上的组件（项目文件里的 `panel`）按"数据是什么"分，共 13 种，取代 0005 里删掉的 21 种面板：

| 数据 | 组件（`type`） | 说明 |
|---|---|---|
| 数值 | 波形 `scope` | 多条曲线随时间变化；开关量画成高低电平 |
| | 数值 `number` | 一个数加单位；数字 / 条形 / 表盘三种样子；超限变红 |
| | 数值表 `values` | 很多信号：当前值、最小、最大、平均 |
| 状态 | 指示灯 `lamp` | 开关量一位一个灯；数值到阈值点灯 |
| 原始数据 | 终端 `terminal` | 一条字节流或报文流，文本或十六进制 |
| | 报文表 `trace` | 一帧一行，点一行看每个字节 |
| 操作 | 按钮 `button`、开关 `switch`、滑块 `slider`、选择 `select` | 各绑定一个设备工具（0007），显示读回的值 |
| 测试 | 结果表 `results` | 本次运行每一项判定 |
| 版面 | 文字 `label`、分组框 `group` | |

- 去掉的旧类型：数据源、属性（改到左栏）、仪表（数值的一种样子）、数字量和状态字（并入指示灯）、状态时间线（并入波形）、报文详情和报文（并入报文表）、控制面板（用分组框装几个操作组件）、XY 图（先不做）。
- **旧项目里存着的旧类型面板在读取时丢掉**，项目其余部分（设备、接线、流程、协议）照常打开；不做迁移。
- 编辑布局时左栏两个页签"组件 / 变量"：组件拖到画布或点一下放到第一个空位；变量拖到空白处按类型生成显示类组件（数值 → 数值，采样块 → 波形，开关量 → 指示灯，字节流 → 终端，报文流 → 报文表），拖到已有组件上就给它加一路。选中组件后左栏是它的属性。

## 原因
- 查了 VOFA+、Serial Studio、Foxglove、NI FlexLogger、dSPACE ControlDesk、Vector CANoe：组件都只有十几到二十个，按数据类型分族，绑定靠拖。
- 旧的 21 种里有多组只是样子不同（数值 / 仪表 / 大数字；数字量 / 指示灯 / 状态字 / 时间线），用户要在相似的东西里挑。
- 用户 2026-11-25 确认按这 13 个做。

## 怎么执行
- 类型、可接的数据流类型、默认大小在 `app/packages/contracts/src/monitor.ts` 和后端 `contracts/monitor.py` 各有一份，改一处必须改另一处；后端的描述同时是 AI 工具 `get_monitor` / `update_monitor` 的说明。
- 前端在 `features/monitor/`：`component-model.ts`（不依赖界面的逻辑，有单元测试）、`panel-kit.tsx`（取读数、调用动作）、`components/`（13 个组件）、`Properties.tsx`（属性和手动绑定）、`LayoutPanel.tsx`（左栏）。
- 每个组件都守这几条：没数据或设备不响应时显示"—"并说明，不停在旧值上；操作类显示读回值，没有读回流的标"设定值"；不能操作时置灰并写原因；绑定对不上时标"绑定失效"。
- 运行页和记录页各有一块画布，同一个组件会同时存在两个实例：组件不能用模块级的状态。
- 新增组件类型先问它是不是已有组件的一种样子；确实是新的一类数据再加。
