# 0002 单仓库；平台与插件靠依赖方向解耦
日期：2026-11-23　状态：有效

## 决定
- 平台和插件放**同一个 git 仓库** `E:\Project\SAGE`（三台电脑同一路径）：平台在 `app/`，SDK 在 `sdk/`，插件在 `plugin/<名>/`。
- 解耦不靠拆仓库，靠规则和检查：

| 规则 | 怎么保证 |
|---|---|
| 依赖只能 `app -> sdk <- plugin` | `pnpm check:boundaries`（`app/scripts/check-plugin-boundary.mjs`），在 `pnpm verify` 里 |
| 平台代码不出现产品插件的名字或设备类型 | 同上，例外清单为空 |
| 两边各自的 Python 环境 | `app/python` 和 `plugin/` 各是独立 uv 项目，平台环境不装产品插件 |
| 测试互不依赖 | 平台测试用 `sdk/demo_plugin`（`demo` 进程内、`demo_isolated` 子进程）；插件测试只用 SDK |
| 交付分开 | `pnpm release` 只出平台安装包；`plugin/tools/pack.py` 出 `.sagedev` |
| SDK 兼容 | 插件声明 SDK 范围，打包写进设备包，平台安装时核对；SDK 改坏旧接口升大版本 |

## 原因
- 平台和插件交付节奏不同，要分别交给客户。
- 拆两个仓库后，三台电脑同步代码要管两个仓库，用户觉得不方便（2026-11-23 否决了"拆两个仓库"）。
- 上面几条都做到，将来真要拆，用 `git subtree split --prefix plugin` 就能连历史拆出去。

## 怎么执行
- 提交：`70209a9` 目录调整，`0778ed2` 解耦。
